# Verification Checklist

- [ ] Acceptance criteria are explicit.
- [ ] Test oracle is independent of the generated implementation.
- [ ] Signals are classified as evidence, revision guidance, model opinion, or approval judgment.
- [ ] Normal cases covered.
- [ ] Boundary cases covered.
- [ ] Invalid/error cases covered.
- [ ] A plausible wrong implementation would fail at least one test.
- [ ] Relevant static/security checks run.
- [ ] Architecture consequences reviewed.
- [ ] Evidence is reproducible by another learner/reviewer.
- [ ] Remaining uncertainty recorded.
- [ ] Property-scoped verification is kept separate from accountable approval.
